1

Session header

Title, project, agent (name, model, provider, sandbox), status active / orphaned / dead. Orphaned and dead need a clear banner, not only a chip.

2

Goal bar

Objective, status (active, paused, blocked, usageLimited, budgetLimited, complete), tokens vs budget, time used. Show the larger of tokensUsed and tokensObserved. Opens the goal timeline. Also hosts the review step: accept, or reopen with feedback.

3

User message

Text and time, plus delivery (pending / accepted / failed / unknown) with retry on failed. Mark steer messages sent mid-turn. Slash commands render as a command card with running, succeeded or failed.

4

Work: thinking and tools

Reasoning streams live, then folds to "Thought for Ns". Tool rows by type: MCP call (server · tool), command (exit status, output), file change (diff), web search. Collapse to one line each; expand for detail.

5

Helper agents

One block per turn. Each helper shows nickname or role, task, status and duration, and opens a read-only transcript. Statuses: pendingInit, running, completed, errored, interrupted, shutdown.

6

Tool approval

From PendingRequest. Shows the action and a countdown from expiresAt. Choices map to allowed once, session, chat, always, or declined. Approval mode can skip it for read-only or all tools.

7

Clarifying question

Options with one recommended, a free-text "Other", and an optional note. Form fields come from responseSchema. Plan approval and secret questions always ask, whatever the mode.

8

Response

Streaming text that settles into the final message. Can contain inline visualizations. Suggested follow-ups sit under the last answer only.

9

Turn receipt

One quiet line: duration, TTFT, tokens and cache hit, helper tokens, privacy findings. "Details" opens the observability drawer below.

10

Q&A audit record

What was asked and answered in this turn, after it resolves. Outcome is answered, auto, expired or interrupted, and autoMode says which mode answered. Secret answers stay hidden.

11

Composer

Slash commands, approval mode picker (ask / readOnly / auto, flag-gated), model and effort settings. Turn state drives the button: send when idle, stop while running, disabled while interrupting.

Open questions for v2

  1. Do plan steps and the running diff get a side panel, or live inline in the turn that changed them?
  2. Should a pending request pin above the composer when it scrolls out of view, so the countdown is never missed?
  3. Is the receipt visible to every user, or only in developer mode? Privacy findings may need to show for everyone.
  4. How much of the tool detail (command output, diffs) should non-developer users see by default?
  5. Where does the goal timeline open: a popover from the goal bar, or a tab in the drawer?
