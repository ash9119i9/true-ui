Build order

  1. Adapter. One function maps Entry, PendingRequest, TurnTrace and session events into the view model app.tsx renders. Components never read contracts directly.
  2. Stream. Messages, steps, helper card and receipt. Most of the visible value lands here.
  3. Live requests and composer. Request card, steer, stop and the mode picker.
  4. Panel tabs. Group every panel event by turn id first, then build the This turn and Session scopes on top. Plan versions, helpers, files and errors keep the turn that produced them.
  5. Insights and dev mode. Timeline, limits, privacy and model context.
  6. Spec update. Every new component added to the truex spec with light and dark values.
Where do live requests go?This page pins them above the composer. The other option is the end of the stream, which keeps the history in one place but can scroll away.
Which repo is the target?This repo's app.tsx runs on sample data. The contracts live in the main app, so the adapter probably belongs there.
Which scope opens first?This page defaults to This turn while a turn runs and Session when idle. The other option is to remember the last scope per tab.
How much trace is public?The receipt shows for everyone. Model context is dev mode only. Should the timeline and privacy findings also sit behind dev mode?
