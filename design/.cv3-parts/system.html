System and next steps

Tokens, color, icons and the build order

Everything on the earlier boards draws from one token set. Today spacing, z-index and motion are literal values scattered across two stylesheet systems, and two icon sets disagree on stroke width. These cards fix the foundations first, then lay out the phases, the CSS cleanup, the bugs to fix along the way and the backend asks in the order they unblock work.

Four of the nine already exist in the shell sprite. Five are drawn here on the same grid.

  1. 1
    Aliases, not new colors deriveThe r2 wireframes used --ok, --bad and --warn. They become aliases for the app's --success-*, --error-* and --warning-* tokens (§8.3), so there is one vocabulary and dark mode comes for free.
  2. 2
    Chart series tokens derivenewSeries map to the helper tone tokens, which were already validated for both modes. Grid and axis tokens stop charts from hard-coding greys. Visualizations are model HTML in a sandbox, so they only get these tokens if the frame passes them in.
  3. 3
    Contrast fixes derive--ink-3 darkens from #849198 to #67757C, and text under 13px moves to --ink-2. Filled buttons use --accent-fg #2A72A3 instead of #3691CD. Ratios are estimates, so a manual check with assistive tech is still needed.
  4. 4
    Nine icons in v2 derivenewAdded to the PATHS map in components/v2/icon.tsx at stroke 1.75 (§8.13). shieldCheck, clock, alert and retry match the shell sprite. shield, shieldAlert, code, coins and copy are new paths.
  5. 5
    Drop lucide deriveLucide's 2px stroke looks heavier next to v2 icons. Swap its imports in these 11 files, then remove lucide-react from package.json once nothing imports it.
