Composer

The composer is the form at the bottom of the chat column and inside the hero on an empty chat. Today it holds the textarea, the Goal chip with BudgetField, the alpha approval-mode picker, Send and Stop. v3 moves everything that shapes the next message onto one action bar: files, agent, model and effort, approval mode and Goal. It adds @-mentions, a visible queue for messages typed during a turn, an explicit Steer button and a Stopping state. The slash-command parser, BudgetField and PrivacyNote keep their current logic.

Source of truth for today's values: chat-ui-schema.md §2. Target design: the composer boards in the v3 wireframe. In this section page means Home in frontend/app/page.tsx. The page's busy means a request is in flight. The page's running means a turn is streaming. Composer receives running through a prop that is also called busy.

Contrast rule for this section: Send, the file icon tile and any other filled button with light text use the --accent-fg fill, not --accent. Text under 13px uses --ink-2. Spacing, z-index and motion tokens (--sp-*, --z-*, --dur-*, --ease-*) come from the Foundations part. The raw values below are today's CSS, so a token replaces each one at the same value.

Behavior

  • Validate size, emptiness, extension and conversation totals on the client first. Invalid files never send a request.
  • With a session: upload starts on pick, up to 2 files at a time proposal D-NEW-04. Use XHR for progress; fetch has no upload progress.
  • Without a session: files are held. On the first Send, ensureSession() runs, held files upload, then the message sends. If any upload fails, the message does not send, the draft stays and the failed chip shows Retry proposal D-NEW-03.
  • Send and Steer are disabled while any chip is uploading. Error chips do not block Send; they are not sent.
  • Remove on an uploaded chip only removes it from the draft. The file stays in the conversation (no delete endpoint). Its row in the Tools panel stays.
  • After a successful send, uploaded chips clear. Today's auto prompt 'Read the uploaded document "{name}" and summarize its key points.' is not inserted from the composer; the person writes their own message.
  • Drag and drop onto the composer and paste of files use the same path. Drop target shows the focus border.
  • Uploaded files feed the Files group of the mention picker.

  • Attach: aria-label="Attach files", title "Attach files (1 MB each)".
  • The chip list is role="list" aria-label="Attached files"; each chip is a listitem.
  • Error chips use role="alert" once. Progress is not announced per tick; announce "Uploaded {name}" in the composer polite region on finish.
  • Remove button: aria-label="Remove {name}". After removing, focus moves to the next chip's button, else the textarea.

  • A dropped .py file is rejected with the wrong-type copy.
  • Send is disabled while a chip shows a progress bar.
  • Files picked on a new chat upload only after Send, and the message waits for them.
  • Tools panel keeps listing uploaded files; its upload control is removed.

Ordering rules

  1. First in, first out. Position is the order shown; reorder changes it.
  2. Only message input queues. Commands, panels and help never queue (commands are refused with the blocked copy; panels and help run at once).
  3. Dispatch starts when running goes false after turn.completed and no pause reason is set. Wait one frame so the final assistant entry renders first.

  5. Steer never touches the queue. A steer goes into the live turn ahead of every queued item.
  6. If the person sends a normal message when idle while items exist (for example after a pause), that message joins the end of the queue and Resume starts it. Nothing jumps the queue except Steer proposal D-NEW-09.
