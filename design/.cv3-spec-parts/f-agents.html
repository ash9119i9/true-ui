Agents, helpers and goals

Everything that works on the user's behalf. The goal strip leads with checkpoint progress, then the token budget, and every stop names one fix. Helpers appear as one "Handed off" node per turn in the stream and as a roster in the Agents tab. Persistent agents get an All agents sheet and the existing create dialog. MCP servers get a tools shelf that finally shows scope, warnings and shadowing, which the API already returns.

Source of truth for today's values: chat-ui-schema.md §4 (Goals) and §5 (Agents, Subagents, Tools and MCP). Target design: the agents boards in the v3 wireframe (design/.cv3-parts/agents.html). Existing visual values: truex-design-spec.html sections Goal tab, Agents tab, Agents roster and New agent dialog. The turn state and the status pill are defined once in Shell (deriveTurnState(), see Topbar); this part only reads them.

Terms. Agent is a persistent specialist stored per tenant (Agent / AgentSummary), mentioned as @handle. Helper is a sub-agent the main agent spawns inside one session (SubAgent). Connected tools are MCP servers attached to an agent. Spacing, z-index and motion tokens (--sp-*, --z-*, --dur-*, --ease-*) come from Foundations. Today's CSS uses --success-bg/--success-text and --warning-bg/--warning-text; this spec names them by their shell equivalents --ok-bg/--ok and --warn-bg/--warn-text at the same values.

Goal data model and status table

Behavior

  • Load: GET /api/agents/:id/mcp. Use profiles for "Yours" and tenantProfiles for attached workspace servers. For admins, profiles also contains tenant servers (legacy); split by scope so each server appears once, in its tab.
  • Attach: POST /api/agents/:id/mcp { profileIds } (at most 50 ids, each at most 200 chars) replaces the caller's attachments. Then onSaved() bumps mcpVersion.
  • Create: POST /api/mcp { name, transport: "http", url, auth, apiKey? }. Edit: PATCH /api/mcp/:id with changed fields only; omit apiKey to keep it. Delete: DELETE /api/mcp/:id, then drop it from selected. Tenant equivalents under /api/tenant/mcp/:id for admins.
  • Workspace tab fetches GET /api/tenant/mcp on first open. 403 sets tenantDenied and shows the note; any tenant route 403 for a non-admin is never shown as an error.
  • Live status (BE-06): subscribe to mcp.status events of the active session for LED and tool count. Sign-in opens the OAuth start URL from BE-06 in a popup; on completion the status event flips to connected. Until BE-06, the LED, tool count and sign-in button do not render and the row shows transport and host only.
  • The topbar tool-health button (Shell) reads the same status and opens this sheet.

Keyboard and a11y

  • Each row: checkbox label = server name; badges and warnings linked via aria-describedby.
  • LED has role="img" and aria-label "Connected" / "Connecting" / "Sign-in needed" / "Can't connect" / "Unavailable".
  • Delete confirm moves focus to "Delete"; Escape or "Keep" returns focus to the Delete icon.
  • Notices use role=status; errors role=alert.

Acceptance

  • A tenant server shows "Workspace" and no edit or delete for a non-admin.
  • A user server with shadowed: true is dimmed and shows the shadowed warning.
  • Editing without typing a key sends no apiKey, and hasKey stays true.
  • Deleting lists the attached agents by name.
  • A non-admin opening Workspace sees the note, not a red banner.
  • Without BE-06, no LED or sign-in control renders.
  • The new-chats note is visible in every state except No agent.
