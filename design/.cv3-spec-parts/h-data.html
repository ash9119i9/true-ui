Other parts reference this one for data; this part links back to them for component detail instead of redefining it.

In this part page means Home in frontend/app/page.tsx. The browser never sees raw runtime data: every shape below is the projection from platform/src/public.ts.

Fix first (production risk, BE-01). api() calls fetch without credentials: "include", and EventSource is created without withCredentials. With AUTH_MODE=google and the frontend on a different origin from the platform, the session cookie is never sent. Every call then returns 401 and the stream never opens. This blocks sign-in in any cross-origin deploy and must land before any P1 screen. The client half is in api() client, the server half in CORS and cookies.

Behavior

  • Overload detection: the second argument is an ApiInit only when it is a plain object with a method key. Existing callers that POST a body object without method keep working.
  • Message shown to the user: body.error verbatim when present, else the fallback below by status. Never show code as the headline; it goes in the ref line (ErrorRef).
  • onAuthError routing: status 401 opens the sign-in sheet. Status 403 with NOT_SESSION_OWNER or NOT_PROJECT_OWNER shows the permission toast and flips the view to read-only. 403 CAPABILITY_DENIED shows the toast only. 403 TENANT_DISABLED and NOT_A_MEMBER open the sign-in sheet in its workspace variant. All other errors go only to the caller. derive
  • Callers that pass quiet: true (sidebar refresh, timings, traces, features) never trigger the sheet; they use warnFailure. The next foreground call will.
  • A 502/503/504 on POST /messages may have been accepted. The composer keeps the clientId and a retry replays it; the server answers { duplicate: true } instead of a second turn (exists).
  • /api/features failure is treated as flags off (exists). GET /api/sessions/:id never fails on runtime outage; it returns snapshot: null and recoveryError (exists).

Acceptance

  • Every request in the network panel carries the session cookie when frontend and platform are on different origins.
  • The EventSource request carries the cookie and opens in google mode cross-origin.
  • api("/api/agents/x", { method: "DELETE" }) sends DELETE; api("/api/projects", { name }) still sends POST.
  • A 401 from any foreground call opens the sign-in sheet once, even if three calls fail together.
  • A 401 from a quiet poll does not open the sheet.
  • A timed-out send shows "timed out (may have been accepted)" and a retry does not create a second turn.

export function deriveFull(i: TurnInputs): TurnStateFull {
  // "idle" (no session) and "connecting" (first open) are not trouble
  if (i.stream.phase === "reconnecting" || i.stream.phase === "disconnected"
      || i.stream.phase === "resyncing") return "reconnecting";
  if (i.failure && !i.retrying) return "failed";
  if (i.running && (i.stop.phase === "acked" || i.runtime?.kind === "interrupting")) return "interrupting";
  if (i.running && i.stop.phase === "requested") return "stopping";
  if (i.running && i.pending.length > 0) return "waiting";
  if (i.running) return "working";
  if (i.send.phase === "accepted" || i.runtime?.kind === "starting") return "starting";
  if (i.busy && i.send.phase === "posting") return "sending";
  if (i.lastTurnEnd === "interrupted") return "interrupted";
  return "idle";
}

export function deriveTurnState(i: TurnInputs): TurnView {
  const full = deriveFull(i);
  return view(full, PILL[full], i);           // label, tone, indicator from the Shell table
}

function reconnectLabel(i: TurnInputs): string {
  switch (i.stream.phase) {
    case "disconnected": return "Disconnected";
    case "resyncing":    return "Refreshing…";
    default:             return i.slowReconnect ? "Still reconnecting…" : "Reconnecting…";
  }
