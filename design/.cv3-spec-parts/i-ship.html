Accessibility, QA and build plan

This part holds the rules that apply to the whole page. It covers the accessibility spec, the responsive QA matrix, the build plan by phase, every backend item, the decisions register, conflicts between parts, the global acceptance checklist, the definition of done and performance budgets. Component parts own their own keys, labels and states. This part joins them up and settles clashes. Where a part and this part disagree on a cross-part rule, this part wins and the clash is listed under Conflict check.

Inputs: the accessibility and responsive boards in design/.cv3-parts/states.html, the build order board in design/.cv3-parts/system.html, design/convo-v3-plan.html, the global gaps in chat-ui-schema.md (lines 18-51) and the finished parts: Foundations, Shell, Composer, Stream, Requests and Agents. The Panel and Data parts were still being written when this part was drafted, so their component ids are not listed here. Link to those parts by section until their ids exist.

Full WCAG validation needs manual testing with assistive technology (VoiceOver on macOS and iOS, NVDA or JAWS on Windows, TalkBack on Android) and an expert accessibility review. The rules and contrast ratios here are a build target. The ratios were calculated from token hex values, not measured on devices. Meeting this spec does not make the page WCAG compliant.

Status live region

There is one polite region, owned by the Shell (Topbar). Every part writes to it through one helper, announce(text, { key }). No part adds its own polite region, with two exceptions that already exist: the search palette result count and the in-thread search count. Errors that need action use role=alert on the element that shows them.

  • The streaming answer is never in a live region. The message list carries aria-busy="true" while tokens arrive and aria-busy="false" once turn.completed or turn.failed arrives. Screen-reader users read the answer on demand.
  • Throttle: one message per 1000ms (Shell). A newer message in the window replaces the queued one. Same text within 5000ms is dropped. proposal D-NEW-SH-07
  • Precedence inside one window: a specific request message beats the generic state message. When a request docks, "Waiting on you" is not also said.
  • Text comes from derived state (deriveTurnState()), never from a component's own copy of it.

Esc order

One handler owns Esc, useEscStack. Each open layer pushes an entry, and Esc runs only the top entry, then calls preventDefault and stopPropagation. This replaces the per-part rules, which say the same thing in different words. proposal D-NEW-SH-01

  1. A menu or combobox list (slash, mention, row menu, goal menu, effort list).
  2. A popover (agent, model, dock popover, Share, tray).
  3. The Other input in a question card, when open and empty.
  4. In-thread search.
  5. A modal (sheet, dialog, palette, drawer). A card inside the batch sheet runs D-06 first, and the next Esc closes the sheet.
  6. Focus context:
    • in a docked request card: D-06 (Cancel option, or focus the composer)
    • in the textarea while editing a queued item: cancel the edit
    • in goal mode: leave goal mode, keep the draft
    • in helper detail: back to the list
  7. With focus in the composer and a turn running: stop the turn.

Esc never stops a turn when focus is outside the composer, and never declines a request when focus is in the textarea.

Target sizes

  • Pointer: every interactive target is at least 24×24px (WCAG 2.2 SC 2.5.8), or has 24px of clear spacing around a smaller target.
  • Touch (@media (pointer: coarse)): the hit area is at least 44×44px. Where the visual stays smaller (26px icon buttons, 20px pills, 18px avatars), a ::after pseudo-element with inset: -9px (or as needed to reach 44px) extends the hit area. Hit areas of neighbours must not overlap, so rows of icon buttons get 4px more gap on coarse pointers. proposal D-NEW-SH-06
  • Known small targets to check: composer ghost cancel 26×26, MCP row icons 26×26, "Sign in" 26px tall, tint circles 26, delegation pill 20, scope badges 18, code block Copy and Wrap, message action buttons, HelperGroup "Open".
  • Inline links in running text are exempt from 2.5.8, but links in rows (citations, file cards) are not.

3. Build plan by phase

Phases follow convo-v3-plan.html and the build order board. Each component's phase tag is in its own block. Where the board and a block disagree, the block's tag is used here and the clash is listed in the Conflict check (C-10, C-11). Components that are still blocked on backend work ship as disabled controls or stay hidden, then light up without a redesign. Panel and Data components are listed by section until their ids exist.

BE-01 (credentials on fetch and EventSource, CORS for the exact origin) is "now". It is not a phase item. It blocks production auth on its own and must land before any P1 PR merges to a shared environment.

7. QA acceptance checklist

Run this for every phase exit, on Chrome, Safari and Firefox (latest), iOS Safari and Android Chrome.

  • Both themes: every surface in light, dark, and system with a live OS switch. No literal colors, and sandboxed visuals re-render on a theme change.
  • All widths: every row of the QA matrix passes, with no horizontal page scroll at 400 and 390.
  • Keyboard only: with no pointer, a user can send, queue, steer, stop, answer each request kind, open and close every popover, sheet and drawer, use the tray, create an agent, attach a file, and open every folded block. Focus is visible at every step and never lands on body.
  • Focus return: each row of the focus table returns focus to the listed target.
  • Esc: each step of the Esc stack runs alone, and one Esc never does two things.
  • Screen reader passes: VoiceOver with Safari (macOS and iOS), NVDA with Firefox or Chrome, TalkBack with Chrome. Landmarks are listed as in §1. A full turn gives "Working" then "Done", with no streamed text read aloud. A docked request is announced once. Every icon button has its name.
  • Reduced motion: every row of the reduced motion table holds, and busy states are still visible without animation.
  • Slow network (Chrome "Slow 3G") and reconnect: drop the connection during a stream. The pill says "Reconnecting", request controls disable with the reconnect copy, and the stream resyncs with no duplicate messages. The draft and the queue survive.
  • Read-only viewer (BE-09): the composer is replaced by the viewer bar, requests show "Waiting on owner", and no send, answer, stop, edit or delete control can be reached by mouse or keyboard.
  • Long chats: a 200-turn chat with code, tools and helpers opens within the budget in §9. Scrolling holds 60fps on the reference machine. JumpToLatest, the outline (P3) and search find turns outside the rendered window.
  • Streaming, no layout jump: while tokens arrive, the content above the stream does not move (CLS 0 for content above the viewport bottom). Auto-follow keeps the bottom pinned only when the user was at the bottom. The work group fold after 600ms does not move the user's reading position. Code blocks reserve their collapsed height as soon as the fence opens.
  • Zoom 200% and 400% reflow, and text spacing override, pass (see §2).
  • Touch: every target meets 44px on a coarse pointer, and hover-only actions are always visible on the last turn.
  • Contrast: the pairs in §1 contrast are spot-checked with a color picker in both themes, and in forced colors mode.
  • Axe or Lighthouse accessibility scan has no critical or serious issues. This is a floor, not a pass (see the note at the top).

8. Definition of done for each component

A component block is done when every item holds. Reviewers tick this list in the PR description.

  • Matches its block: anatomy, sizes, tokens, states, copy and data interface. Any change goes back into the spec in the same PR.
  • Uses tokens only. No literal color, spacing, z-index or duration in its CSS.
  • Every state in its States table can be reached in Storybook or a test fixture, in light and dark.
  • Every acceptance item in its block is an automated test (unit, component or Playwright), or is marked "manual" with a reason.
  • Keyboard and a11y subsection implemented: roles, names, focus return and key paths. Icon-only buttons pass the label lint rule.
  • Announcements go through announce() only, and use the exact strings in §1.
  • Reduced motion and forced colors checked.
  • Works at 400px and inside the ≤900 drawer, where it can appear there.
  • Backend-blocked parts show their fallback state and are behind a capability check, not a commented-out block.
  • Proposal values cite their D-id in code comments, so the value can be found when the decision changes.
  • No new legacy class names (pipeline rule), and no Tailwind classes.
  • Render cost stays within the performance budget for stream components.

When to virtualize the list

D-NEW-SH-03. Proposed rule: render every turn up to 150 turns, or 3,000 DOM nodes in the list, whichever comes first. Above that, switch to a windowed list that keeps the latest 40 turns and the viewport's neighbours (2 screens above and below) mounted. The rest become measured placeholders, with heights cached by turn id.

  • The streaming turn, any turn with a docked request anchor, and any turn holding focus are always mounted.
  • Heights come from a ResizeObserver per mounted turn. Unknown heights use a per-kind estimate and are corrected without moving the reading position (scroll anchoring).
  • Screen readers: a turn that is not mounted can't be read in browse mode. Keep the turn article headings in a hidden outline list, so a user can jump to a turn by heading. ThreadSearch (P3) and BE-16 content search cover find.
  • Browser find misses unmounted turns. This is why C-01 is rechecked when virtualization lands.
  • Before that point, the older work group collapse (sm-older) is the first way to cut DOM size.
