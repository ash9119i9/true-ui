How to use this spec

Each component block lists where it lives in code, its anatomy and measurements, the tokens it uses, a states table, the data it reads, its behavior and keyboard rules, its copy and its acceptance criteria. Every item carries one tag that says whether it can be built today.

TagMeaningWhat a developer does
existsThe data and behavior exist in the current contract.Build it.
deriveNeeds client-side logic only. No API change.Build it, following the derivation rule given.
backendNeeds a field or endpoint that doesn't exist. Each one has a BE-xx id in the backend table.Build the UI behind a flag, or wait for the backend item.
proposalA value or behavior the product team hasn't confirmed. Each one has a D-xx id in the decisions table.Build the default shown, and don't treat it as final.
About sample content. Names like Qlik Analyst, Atlas, Juno, Priya N., the onboarding plan scenario, model names, request ids and error codes are examples only. Real values come from the data fields named next to them.

Build order and ownership are in A11y, QA, build plan. Every schema component appears in the coverage matrix, either with a spec location or with the reason it's out of scope.
