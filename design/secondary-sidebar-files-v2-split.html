Two sizes 360 · 560

No drag handle, nothing saved. The expand/shrink button in the panel header switches size; list views open at 360, an agent or file opens at 560. Each mode keeps its size until reload.

  • The chat keeps 480px (at 360) or 640px (at 560). The sidebar gives way first, then the panel floats over the chat.
  • Phone (≤720px): the panel is the only drawer and the size button is hidden.

File card chat

Ends the reply, below the last paragraph. "N files · N ready", then up to three rows: type tile, name, type and size, who made it, version, status, Open and a separate Download.

  • "+N more" opens the full list in the panel.
  • Writing… shows a spinner; a failed export shows an error chip and Retry lives in the viewer.
  • Hovering a file lights it in both places.

Files tab + viewer panel

Files are grouped under the reply that made them. The viewer has back, "1 of N", a stats row, Preview / Source / Changes, and Download, Copy, Open in new tab.

  • md and docx reflow as a document; xlsx and csv show a grid with sticky header and first column that scrolls on its own.
  • html runs in a sandboxed iframe with no same-origin access and a strict CSP.
  • At 360 the viewer still works and offers "Expand for a wider preview".

Rules

  1. Open never leaves the chat. It opens the viewer in the panel at 560; Download is always its own button.
  2. Previews never scroll the panel sideways. Wide grids scroll inside their own frame.
  3. States are explicit: Writing… (skeleton, actions disabled), Ready, Failed (error banner with Retry).
  4. Versions: a badge appears from v2; the Changes tab shows a word-level diff against the previous version.
  5. Clicking another tab closes the viewer; Esc returns to the file list.

Open questions

  • Should Files be its own tab (current), or a section at the top of Activity to keep five tabs?
  • For wide files (spreadsheets, HTML), is Open in new tab better than growing the panel past 560?
  • Open in new tab uses a Blob URL, which shares the app's origin. For agent-made HTML, should it go to a separate sandbox domain instead?
  • Should the card show every file, or only the "primary" one with the rest behind "+N more"?
  • Does Download all (.zip) belong in the chat card as well as the Files tab?
